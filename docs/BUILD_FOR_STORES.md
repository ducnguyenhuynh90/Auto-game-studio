# Build the app for Google Play and the App Store

For the team that submits **Mắm Village** with its own Google Play and Apple accounts.

**The mobile app is `mobile/`: a native React Native app (Expo SDK 58, React Native 0.88), with no
WebView.** It runs the game's own code from `src/` (rules, every screen, the 3D world, friends), drawn
natively with Skia (menus) and OpenGL ES (3D). So the app has every feature of the web game and matches
the store screenshots and video in `store/`. The Android and iOS projects are generated by Expo
(`npx expo prebuild`) and are not committed. Icons and splash art: `mobile/assets/`.

> Older versions are kept for reference only: `archive/capacitor/` (the WebView app) and the git history
> of the first hand-written React Native screens. Don't ship them.

## 0. Get the code and tools
```bash
git clone https://github.com/ducnguyenhuynh90/Auto-game-studio.git
cd Auto-game-studio/mobile
npm ci                                 # Node 22 LTS
```
- **Android:** JDK 17 and the Android SDK (easiest: install Android Studio). On a Mac,
  `npm run phone:setup` at the repository root installs everything (docs/PHONE_TESTING.md).
- **iOS:** a Mac with Xcode 16 or newer, signed in to your Apple Developer team, and CocoaPods.

## 1. Build settings (`.env.local`)
Copy `build.env.example` to `mobile/.env.local`. The public Supabase values (cloud saves, Google sign-in,
friends) are already filled in. Add the signing values for the store you're building. Export them to
the shell before building (the app reads `VITE_*` or `EXPO_PUBLIC_*` names at build time):
```bash
set -a; source .env.local; set +a
```

| Setting | Turns on | If left empty |
|---|---|---|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (filled in) | Cloud save, Google / Apple sign-in, Friends, invites, Delete account | Guest-only, saved on the phone |
| `EXPO_PUBLIC_GA_MEASUREMENT_ID`, `EXPO_PUBLIC_GA_API_SECRET` | Google Analytics (players opt in) | No analytics |
| `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | A Play-ready signed `.aab` | Signed with the test key (Play refuses it) |
| `MAM_VERSION_NAME`, `MAM_VERSION_CODE` | The version shown and the build number | 1.0.0 / 1 |

## 2. Google Play (Android)
1. Create the upload key once and keep it safe (Google Play App Signing holds the real app key; a lost
   upload key can be reset through Play support):
   ```bash
   keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```
   Put its path and passwords in `.env.local`. Raise `MAM_VERSION_CODE` by 1 for every upload.
2. Build the release bundle:
   ```bash
   cd mobile
   set -a; source .env.local; set +a
   npx expo prebuild --platform android --no-install
   cd android && ./gradlew bundleRelease   # → mobile/android/app/build/outputs/bundle/release/app-release.aab
   ```
3. Play Console → create the app (`com.mamvillage.app`) → **Testing → Internal testing → Create release**
   → upload the `.aab`. Google requires the first upload to be done by hand.
4. Prefer Android Studio? After `npx expo prebuild`, open `mobile/android` → Build → Generate Signed Bundle.
5. A test APK for any phone: `cd mobile/android && MAM_SIGN=tester ./gradlew assembleRelease`
   → `mobile/android/app/build/outputs/apk/release/app-release.apk`.

## 3. App Store (iOS)
1. App Store Connect → Apps → **+** → New app, bundle id **`com.mamvillage.app`**.
2. On the Mac:
   ```bash
   cd mobile
   set -a; source .env.local; set +a
   npx expo prebuild --platform ios       # makes mobile/ios and installs the pods
   xed ios                                 # opens the workspace in Xcode
   ```
3. In Xcode: the app target (the one with the Mắm Village icon) → *Signing & Capabilities* → choose your Team (automatic signing). Under
   *General*, set **Version** (e.g. 1.0.0) and **Build** (raise it for every upload).
4. Pick **Any iOS Device (arm64)** → **Product → Archive** → Organizer → **Distribute App → App Store
   Connect → Upload**. The build appears in TestFlight after Apple's processing (10-30 minutes).

Or let GitHub do it: add the App Store Connect secrets (docs/STORE_RELEASE.md), then **Actions →
Native apps (Android + iOS) → Run workflow → tick testflight**.

## 4. Before the first submission
- Supabase → Authentication → URL Configuration → Redirect URLs must include
  `com.mamvillage.app://auth/callback` (sign-in returns to the app through it).
- Store listing, screenshots, video and SEO copy: `store/listing.md`.
- Privacy answers (Data safety / App Privacy): docs/STORE_RELEASE.md §5.
- Account deletion is in the app (Settings), as both stores require.

## When something goes wrong
- **The app shows an old version of the game:** build again; Metro bundles `src/` fresh each build. For a
  stubborn cache: `npx expo start --clear` once, or delete `mobile/android/app/build`.
- **"SDK location not found" / wrong Java:** `npm run phone:setup` (Mac) or install Android Studio and
  JDK 17, then open a new terminal.
- **Release build has the test key:** the `ANDROID_*` variables weren't exported in this shell
  (`set -a; source .env.local; set +a`), or `MAM_SIGN=tester` is set.
- **iOS "No signing certificate":** pick your Team in Signing & Capabilities, and make sure the Apple
  ID in Xcode → Settings → Accounts belongs to that team.
- **Google sign-in doesn't return to the app:** the redirect URL `com.mamvillage.app://auth/callback` is
  missing in Supabase → Authentication → URL Configuration.
- **Changed `app.json` or a native package:** run `npx expo prebuild --clean` to regenerate the projects.
